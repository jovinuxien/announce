# SQL scripts for announce_reactive_db

| File | Purpose |
|---|---|
| `announce_reactive_db.sql` | **Generated.** Full bootstrap: creates the database and the `announce` user, then every table. Run as a MySQL administrator: `mysql -uroot -p < announce_reactive_db.sql`. Drops the database first, so it is a reset, not an upgrade. |
| `announce_table.sql` | Source: the base tables inherited from litemall, renamed `announce_*`, with the announce read model: `announce` (shared columns of every kind) plus `announce_goods_detail`, `announce_job`, `announce_event` and the goods children keyed by `announce_id`. `announce_category.kind` separates the goods, job and event trees. `announce.moderated_by` / `moderation_reason` record staff withdrawals and expiries; `announce_refresh_token` holds the hashed refresh tokens of both edges; `crawled_listing` (with the quality grade and liveness columns of 2026-10-17), `listing_category_map` and `listing_import_run` are the crawled-listing read model (`doc/crawled-listings.md`). |
| `announce_auction_chat.sql` | Source: the 6 auction tables plus columns added to user and order. Re-runnable on an existing database. |
| `announce_messaging.sql` | Source: the 4 messaging tables (`announce_conversation`, `announce_conversation_participant`, `announce_chat_message`, `announce_bulletin`), read models of the `messaging` module's Conversation aggregate. Re-runnable. |
| `build_announce_reactive_db.sh` | Regenerates `announce_reactive_db.sql` from the three sources above. Edit the sources, never the generated file. |
| `announce_user.sql` | Recreates only the `announce` user and its grants. |
| `announce_data_en.sql` | Optional development seed (English only): `mysql -uannounce -p announce_reactive_db < announce_data_en.sql`. One administrator (`admin123`) and one member (`user123`), roles and permissions, the category trees of the three kinds (GOODS, JOB, EVENT), a few brands and keywords, the regions of Denmark (country, 5 regions, 98 municipalities) and Sweden (country, 21 counties, main municipalities) and 21 published sample announces owned by member 1. The litemall demo catalogue (Chinese categories, brands, goods, ads, topics) is gone. |
| `announce_reseed_en.sql`, `reseed_en.sh` | In-place migration of a live database that still holds the litemall demo content: removes the 7-digit litemall goods and the legacy ad/topic/comment/issue/log rows, reloads categories, brands, keywords, regions and the sample announces, remaps application-posted announces whose category disappeared, and fills `region_id` from the city name. Keeps members, administrators, tokens, crawled listings, orders and conversations. The script backs the affected tables up first, then deletes the old documents from the OCS index; run the admin reindex afterwards. |
| `litemall_schema.sql` | Legacy litemall database bootstrap. Not used by this project. |

Design notes for the auction and chat tables: `doc/auction-chat-schema.md` (messaging: `doc/messaging-context.md`); for the announce read model: `doc/announce-management-context.md` section 8.
